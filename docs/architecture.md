5: 3: ## 一、 基础设施与部署
6: 4: - **前端托管**：Cloudflare Pages（免费层，支持 Astro SSR，绑定 `ziji.zh.kg`）。
7: 5: - **后端即服务**：Supabase（免费层）。
8: 6:   - Auth（邮箱/OAuth 混合）
9: 7:   - Database (PostgreSQL + RLS)
10: 8:   - Realtime（大厅 Feed 实时流 + 游戏联机）
11: 9:   - Edge Functions（游戏裁判、预签名上传、留言限流）
12: 10: - **图床存储**：Tigris (S3 兼容，5GB 免费)。

14: 12: ## 二、 路由与访问
15: 13: - **主站**：`ziji.zh.kg`（首页动态大厅、编辑器、圈子、游戏）。
16: 14: - **个人主页**：`ziji.zh.kg/[username]`。无需登录直接访问；若未发布则返回 404。

18: 16: ## 三、 路由规范与命名限制
19: 17: - **路径格式**：`/[username]`。
20: 18: - **命名规则**：严格正则校验 `^[a-z0-9_]{3,20}$`。
21: 19: - **防冲突**：维护系统保留字黑名单（admin、api、arcade、circle、login 等）。

23: 21: ## 四、 分享与 SEO 策略
24: 22: - **动态 OG 标签**：利用 Astro SSR，访问 `/[username]` 时读取该用户信息，动态注入 og:title、og:image（画布首图或专属封面）。
25: 23: 
26: 24: ## 五、 主站首页（类朋友圈）与扩展玩法
27: 25: - **核心形态**：个人动态大厅。第一眼看到关注成员的最新动态（文字、图片、作品、战绩），未登录用户看社区精选。
28: 26: - **备选扩展（预留）**：微缩世界地图（2D 游戏化大厅）。
29: 27: - **动态流形态**：混合流。包含用户主动发布的内容，以及系统自动推送的聚合动态（发布文章、更新主页、游戏胜局）。
30: 28: - **发布机制**：采用经典后台逻辑，导航栏提供“发布”入口进入独立 CMS 编辑器，不在流内直接发快讯。
31: 29: - **内容与展示分离**：博客、图集、碎碎念是独立数据层，画布是展示层。画布通过组件拉取数据，长文正文不塞进画布 JSON。
32: 30: - **内容后台（Dashboard）**：经典侧边栏布局（文章、图集、碎碎念、主页设置）。
33: 31: - **全局视觉定制**：预设组合包 + 细节微调（官方主题预设 + 主色/字号微调）。
34: 32: 
35: 33: ## 六、 圈子（全站 Feed）数据隔离
36: 34: - **数据获取**：使用 PostgreSQL 只读视图 `public_feed_view`，仅暴露 `is_public = true` 的公开数据。
37: 35: - **权限配置**：为该视图配置独立 RLS 策略（允许匿名 SELECT），与个人主页数据严格隔离。
38: 36: 
39: 37: ## 七、 注册与鉴权
40: 38: - **模式**：混合注册。默认邀请制，可通过 `registration_mode` 开关切为开放注册。
41: 39: - **权限防线**：Supabase RLS 强制隔离。`draft_data` 仅本人读写；`published_data` 匿名可读（需 `is_public = true`）。
42: 40: 
43: 41: ## 八、 编辑器与画布核心 (Free Canvas)
44: 42: - **核心定位**：轻量绝对定位图层系统，从零实现。
45: 43: - **手势库**：`interact.js`（仅负责手势，渲染由 DOM/JSON 驱动）。
46: 44: - **响应式**：默认固定画布尺寸（1440×900），移动端等比缩放；高级选项支持独立移动端画布。
47: 45: - **模块库**：
48: 46:   1. 基础：富文本、单张图片、外链按钮、矩形背景板、分割线。
49: 47:   2. 聚合：文章列表、橱窗画廊、碎碎念卡片。
50: 48:   3. 个人化：名片、音乐播放器、社交链接组。
51: 49: - **数据可见性**：公开主页只渲染用户本人的文章、作品、碎碎念。
52: 50: - **画廊数据结构**：独立相册表（Gallery）。画布画廊模块仅保存相册 ID，实现作品库与展台分离。
53: 51: - **聚合模块溢出**：固定尺寸，内容超出时内部滚动，严禁撑开破坏画布布局。
54: 52: - **画布安全边界**：单画布元素上限 100 个；单元素最小 20px，最大不超过画布宽高的 3 倍。
55: 53: 
56: 54: ## 九、 草稿与发布机制
57: 55: - **双版本字段**：`pages` 表包含 `draft_data` (JSONB) 与 `published_data` (JSONB)。
58: 56: - **流程**：编辑器实时存 `draft_data`；点击“发布”复制至 `published_data` 并设置 `is_public = true`；公开主页只读 `published_data`。

60: 58: ## 十、 编辑器交互设计
61: 59: - **左侧模块面板**：分类折叠手风琴（基础/聚合/个性化），支持点击添加或拖拽至画布。
62: 60: - **画布手势**：`interact.js` 支持拖拽、缩放、图层调整。
63: 61: - **右侧属性面板**：三个 Tab —— 内容（文字/图片/数据源）、样式（字号/颜色/圆角/透明度）、动画（预设库 + 滑杆，GSAP 驱动）。
64: 62: - **图层管理**：桌面端完整图层面板（树状拖拽），移动端简化为四向按钮。
65: 63: - **对齐与吸附**：智能吸附（阈值 5px）+ 辅助参考线。
66: 64: - **撤销/重做**：Command Pattern，支持 `Ctrl/Cmd + Z` 与 `Ctrl/Cmd + Shift + Z`。
67: 65: - **自动保存**：防抖（停止操作 2s 后保存），状态栏显示“保存中/已保存/失败”。
68: 66: 
69: 67: ## 十一、 内容录入与编辑器形态
70: 68: - **文章/碎碎念**：双栏 Markdown 编辑器（左输入右预览）。
71: 69: - **数据存储**：仅存 Markdown 纯文本。
72: 70: - **渲染管道**：统一解析 Markdown，经 DOMPurify 清洗输出。
73: 71: - **长文阅读形态**：独立阅读页 `/post/[id]`，专属沉浸排版 + 独立 OG 标签。
74: 72: 
75: 73: ## 十二、 安全与输入过滤
76: 74: - **富文本/文章**：Markdown 输入，保存前与渲染前经 DOMPurify 清洗，剥离脚本与恶意协议。
77: 75: - **画布数据**：仅接受预定义元素类型（白名单），拒绝任意 HTML 渲染。
78: 76: - **图片上传**：Edge Function 签发 Tigris 预签名 URL，Secret Key 永不出现在前端。
79: 77: 
80: 78: ## 十三、 视觉与动效规范
81: 79: - **默认字体**：JetBrains Mono（JBM），保证 0O/1lI 清晰可辨。
82: 80: - **动效基础**：GSAP 管理生命周期，与 Astro 岛架构配合，避免转场冲突。
83: 81: - **视觉基调**：允许根据动效匹配度微调，当前参考 Akari 暖色纸感。
84: 82: 
85: 83: ## 十四、 主站互动与大厅策略
86: 84: - **访客互动**：轻互动原则。默认支持“点赞”，画布模块库提供“留言板（Guestbook）”组件，由主页主人决定是否展示。
87: 85: - **留言板安全**：必须基于 Supabase Auth 登录；纯文本/极简 Markdown；DOMPurify 清洗；Edge Function 限流（每分钟最多 3 条）。
88: 86: 
89: 87: ## 十五、 游戏厅与联机扩展
90: 88: - **集成形态**：独立主站路由 `/arcade`，游戏重资产与画布彻底隔离。
91: 89: - **画布联动**：主页画布可放“游戏战绩模块”，展示胜局或在线好友，点击跳转 `/arcade`。
92: 90: - **大厅展示策略**：只展示“正在进行中”的对局和参与者，通过记录开始/结束驱动状态。
93: 91: - **房间创建与加入**：玩家创建房间后处于私密等待，**生成专属邀请链接与独立房间号**。好友通过链接直达或输入房间号加入。开局后才推送到大厅。
94: 92: - **异常掉线**：结合 Realtime Presence（心跳），掉线超时自动结束对局并释放资源。
95: 93: 
96: 94: ## 十六、 实时通信与大厅 Feed
97: 95: - **大厅 Feed 实时流**：前端通过 Supabase Realtime 订阅 `posts` 表的 INSERT 事件，新动态实时插入当前页面流顶部，无需刷新。
98: 96: - **连接数控制**：合理利用 200 并发额度，公开主页和后台编辑器不开启无用订阅。
99: 97: 
100: 98: ## 十七、 内容层级与展示形态
101: 99: - **动态（Moment）**：轻量短内容（上限 300 字 + 少量图），直接在大厅 Feed 展开。
102: 100: - **文章（Article）**：使用 Markdown 编辑器，有标题、封面，大厅只展示摘要卡片，点击进入 `/post/[id]`。
103: 101: - **层级隔离**：长短内容在展示和交互上严格区分，防止大厅被长文打乱节奏。
104: 102: 
105: 103: ## 十八、 站内搜索机制
106: 104: - **技术选型**：Pagefind 纯静态搜索方案，不占用数据库算力。
107: 105: - **搜索范围**：构建时已生成的文章页和公开主页。
108: 106: - **限制**：动态和刚发布未触发构建的新文章暂不进入索引。
109: 107: - **索引更新**：发布正式文章时触发 Cloudflare Deploy Hook 重建。为防止消耗构建额度，前端加防抖时间锁（如每小时最多 3 次）。
110: 108: 
111: 109: ## 十九、 新手引导与模板系统
112: 110: - **模板优先**：新用户创建主页时，预设多套高质量模板（博客风、画师展、极简名片），不提供纯空白画布。
113: 111: - **开箱即用**：选模板后画布直接铺好整套排版，用户只需替换内容和图片。
114: 112: 
115: 113: ## 二十、 画布背景定制
116: 114: - **默认方案（A）**：纯色与双色渐变（提供调校预设），渲染成本极低，保证首屏极速。
117: 115: - **进阶选项（B）**：允许高级用户上传自定义背景图（无缝底纹或全图），系统严格限制图片大小和分辨率。
118: 116: 
119: 117: ## 二十一、 公开主页的导航与归属
120: 118: - **返回主站机制**：采用极简悬浮角标（如右下角“⚡ ziji.zh.kg”）。点击可返回主站大厅，不破坏画布整体美感，同时保留主站品牌露出。
121: 119: 
122: 120: ## 二十二、 视图过渡与动效
- **路由切换**：采用 Astro 原生 View Transitions（`<ClientRouter />`）。页面跳转采用平滑淡入淡出或位置形变，配合 GSAP 提升站点的整体高级感，避免生硬的白屏刷新。

## 二十三、 Astro 工程化与渲染策略
123: 121: - **严格隔离架构**：
124: 122:   - **公开侧**（主页、文章、圈子）：优先使用 Astro SSR/SSG，禁用重型框架水合，仅极轻量原生 JS 处理懒加载和音乐。
125: 123:   - **后台侧**（编辑器、Dashboard）：作为重度 React 岛（`client:only`）独立打包，只在登录访问 `/editor` 或 `/dashboard` 时加载。
126: 124: 
127: 125: ## 二十四、 账号注销与数据合规
128: 126: - **软删除与冷静期**：注销后进入 30 天冷静期（无法登录、主页 404、内容不展示）。
129: 127: - **彻底清理**：30 天后由定时任务（pg_cron）物理删除数据库记录，并清理 Tigris 上的所有图片。
